# 日志高亮使用说明

Xu 的日志高亮会在 SSH 终端输出进入终端模拟器之前，按规则给日志里的字段插入颜色。它不会修改服务器上的日志文件，也不会影响命令本身。

> 只对 **SSH 标签** 生效；本地 PowerShell 标签暂不支持。
>
> 只对 **开启之后的新输出** 生效。已经打印在回看缓冲里的旧日志不会重绘。

## 最简单的用法

1. 打开 **设置 → 终端**，向下滚动到 **日志高亮**。
2. 确认 **启用日志高亮** 已打开（默认打开）。
3. 连接服务器，`tail -f` 一个日志文件，或执行一条会输出日志的命令。
4. 新出现的日志会自动着色。

默认规则会处理常见格式，例如：

```text
2026-11-11 15:09:21.041 INFO  [main] com.example.Foo - started
[1a66c70d36534ffb819a187ef50090e8] 2026-11-11 15:09:21.041 [http-nio-8085-exec-21] INFO  com.peak.ddt.config.aspect.TraceIdFilter - 接收到请求
```

预期效果：

- Trace ID、时间戳 → 灰
- `TRACE` / `DEBUG` → 灰 / 蓝
- `INFO` → 绿
- `WARN` → 黄
- `ERROR` / `FATAL` → 红 + 加粗
- `[线程名]` → 青
- `com.example.Foo` 这类 logger → 紫
- IP → 亮青
- HTTP 方法 → 蓝 + 加粗

## 两个概念

配置分成两层，先理解这两层就不会乱：

| 层 | 作用 | 在哪里 |
| --- | --- | --- |
| **日志格式** | 判断“哪一行算日志”，决定是否进入规则匹配 | 规则与格式 → 日志格式 |
| **规则** | 决定“日志里的哪些字段、用什么颜色” | 规则与格式 → 规则 |

一行日志必须**先通过格式判定**，然后才会被规则着色。格式不通过，规则一条都不会执行。

## 打开规则编辑器

**设置 → 终端 → 日志高亮 → 规则与格式**，会打开一个带两个页签的窗口：

- **规则**：字段颜色规则
- **日志格式**：识别日志行的格式

所有修改即时生效，关闭设置时自动保存。

## 规则页

每条规则包含：

- **名称**：只用于辨识
- **匹配**：Go 正则表达式；打开「关键字」后改为普通字符串匹配
- **颜色**：终端 16 色调色板中的颜色，点击色块选择
- **关键字**：不按正则，按字面文本匹配
- **整行**：匹配成功后给整行上色
- **加粗**：匹配部分加粗
- **启用**：临时停用而不删除
- **上移 / 下移**：调整优先级
- **删除**

规则从上往下按顺序匹配，**先命中的规则优先**；重叠部分不会重复着色。整行规则放在最前会覆盖整行，放在后面只补前面规则没占用的部分。

底部按钮：

- **添加规则**：新增一条规则
- **恢复默认**：恢复通用日志规则（会覆盖当前规则）
- **完成**：关闭窗口

如果正则写错，卡片里会显示红色错误；这条规则会被跳过，其他规则继续工作。

### 关键字、整行、加粗怎么选

**关键字**

- **关闭（默认）**：匹配框按**正则表达式**解释，`\[`、`\d`、`.*` 等有特殊含义。
- **打开**：按**普通文本**匹配，`[`、`.`、`\` 都按字面字符处理；区分大小写。
- 例：想匹配字面文本 `[ERROR]`，打开关键字；想匹配 `^\[[0-9a-f]{16,64}\]` 这种模式，必须关闭关键字。

**整行**

不是“整行都要匹配”，而是“规则在行内任意位置命中后，给整行上色”。适合“只要出现 ERROR 就把整行标红”。

**加粗**

只给命中的片段加粗；配合「整行」时整行加粗。

以截图里的 `Trace ID` 规则为例：`^\[[0-9a-fA-F][0-9a-fA-F-]{15,63}\]` 是正则，所以「关键字」保持关闭；它匹配行首 16–64 位的十六进制 Trace ID，颜色选中第 8 号灰色。

## 日志格式页

内置格式始终生效，不需要配置：

- ISO 时间戳：`2026-11-11 15:09:21.041`
- 级别开头：`[INFO] ...`、`[ERROR] ...`
- Nginx：`192.168.1.1 - - [...]`
- JSON 日志：`{"timestamp":...}`、`{"level":...}`
- 带 Trace ID 前缀：`[1a66...] 2026-11-11 ...`（行首 160 字节内的前缀会先被跳过再找时间戳）

如果某个服务的日志格式不在上面，可以添加自定义格式：

1. 切到 **日志格式** 页
2. 点 **添加格式**，或直接点页面上方示例右侧的 **使用**
3. 填名称和正则；正则从**行首**匹配（内部会包成 `^(?:...)`）
4. 勾选启用

页面里的 **示例** 可以直接点「使用」添加：

- `^\[MYAPP\]`：匹配 `[MYAPP]` 开头的行
- `^[A-Z][a-z]{2}\s+\d{1,2}\s+\d{2}:\d{2}:\d{2}`：匹配 syslog 时间
- `^\[[0-9a-fA-F-]{16,64}\]\s+\d{4}-\d{2}-\d{2}`：匹配 `[traceID] 2026-11-11` 开头

下方的 **测试一行** 可以粘贴一条真实日志，实时看到：

- 是否会被识别为日志行
- 规则命中了几处
- 是否因为含 ANSI 颜色码或回车符而被原样放行

新添加的格式默认填入 `^\[YOUR_LOG_PREFIX\]`，把它改成你的日志行开头即可。

示例：

```text
^\[MYAPP\]                                   # [MYAPP] 开头的业务日志
^[A-Z][a-z]{2}\s+\d{1,2}\s+\d{2}:\d{2}:\d{2}  # syslog，例如 Nov 11 14:52:04
^\[TRACE\]                                   # 固定前缀
^\[[0-9a-fA-F-]{16,64}\]\s+\d{4}-\d{2}-\d{2}  # [traceID] 后跟日期
```

格式只是“入场券”，具体颜色仍由规则决定。自定义格式是**追加**的，不会覆盖内置格式；可以添加多条、逐条启用/禁用、删除，或一键清空。

## 「仅处理日志行」开关

默认打开。打开时，只有通过格式判定的行才会跑规则，普通命令输出（`ls`、`cat README` 等）不会被误伤。

如果日志格式比较特殊、又不想维护格式列表，可以关掉它：所有纯文本行都会跑规则。含 ANSI 颜色的行、带 `\r` 的进度条、vim/htop 等全屏程序仍然会原样放行。

## 预设

**设置 → 终端 → 日志高亮 → 预设** 提供：

- **通用日志**：时间戳、级别、线程、logger、IP、HTTP 方法
- **Nginx**：客户端 IP、时间、请求、2xx/3xx/4xx/5xx
- **JSON 日志**：`timestamp`、`level`、`logger`、`message`
- **自定义**：保留当前规则，不做修改

切换预设会覆盖当前规则，但**不会清空自定义日志格式**。预设覆盖后想恢复通用规则，可以再选「通用日志」，或在规则编辑器里点「恢复默认」。

## 颜色和配色方案的关系

规则颜色使用终端调色板的索引 0–15，不是固定十六进制色。切换 **设置 → 配色** 里的终端配色后，日志颜色会自动跟着新配色变化。

规则编辑器里的色块显示的就是当前终端配色下的实际颜色。

## 快速验证

在 SSH 终端里执行（只对新输出生效）：

```bash
printf '%s\n' '2026-11-11 15:09:21.041 INFO  [main] com.example.Foo - hello'
printf '%s\n' '[1a66c70d36534ffb819a187ef50090e8] 2026-11-11 15:09:21.041 [http-nio-8085-exec-21] INFO  com.peak.ddt.config.aspect.TraceIdFilter - test'
```

第一条验证内置 ISO 时间戳格式，第二条验证 Trace ID 前缀格式。

## 常见问题

**完全没有颜色**

- 确认 **启用日志高亮** 是打开的
- 确认看的是 SSH 标签，不是本地 PowerShell
- 确认运行的是包含该功能的最新构建；旧进程需要关闭后重新启动
- 已经打印的旧日志不会重绘，触发一条新日志再看
- 如果打开了「仅处理日志行」，确认这一行能通过格式判定

**只有部分行有颜色**

- 续行（`请求: ...`、`时: 0 ms`、`--end--`）没有时间戳/级别，默认不算独立日志行
- 这一行没有匹配任何规则；可以添加规则
- 格式判定没通过；切到「日志格式」补一条自定义格式

**某一行本来有颜色，但没有被高亮**

- 这一行包含 ANSI 颜色码（例如程序自己输出的彩色日志），会整行原样放行，避免破坏程序颜色
- 全屏程序（vim、htop、top）和进度条也会原样放行

**正则报错**

- 规则/格式卡片里会显示红色错误，修正后自动恢复；错误规则不影响其他规则

**左侧监控和文件面板的文字没有变色**

- 它们是应用 UI，不是终端；日志高亮只作用于终端输出

**设置没有保存**

- 关闭设置弹窗时会保存；只关闭规则编辑器不会保存到磁盘
